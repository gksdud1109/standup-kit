# 업무보고 초안 만들기

로컬 여러 레포의 커밋을 모아 작업 흐름별 보고서를 만든다.

## 1단계 — 자료 수집 (반드시 먼저 실행)

셸에서 아래 두 명령을 실행하고 출력을 확보한다. **건너뛰지 않는다.**

```bash
# 어제 보고서 (없으면 "(없음)")
cat "$HOME/.standup/log/$(date -v-1d +%F 2>/dev/null || date -d yesterday +%F).md" 2>/dev/null || echo "(없음)"

# 오늘 커밋
standup
```

기간을 지정받았으면 그 문자열을 **통째로 따옴표에 넣어** 인자로 준다.

```bash
standup "3 days ago"
```

`standup: command not found` 가 나오면 `$HOME/.local/bin/standup` 을 직접 실행한다.
그래도 없으면 설치 안내만 하고 멈춘다. 커밋을 직접 `git log` 로 긁어 보고서를 만들지 않는다 —
저자 필터와 레포 탐색 규칙이 스크립트에 있다.

## 2단계 — 형식

````
# admin < PID 통합 작업
- 원장 정합성 검증 — 이벤트 원장과 포인트 원장 전량 분해, 미확인 차이 없음
- 문의 어드민 연동(백엔드) — 문의 전 유형 조회로 확장
  - 답변 등록 API 신규
  - 첨부 이미지 조회 API(S3 presigned) 및 IAM 정책 추가
- 문의 등록 검증 완료
````

- `# ` 제목은 **작업 흐름**이다. 레포명이 아니다. 여러 레포에 걸친 하나의 일은 **한 제목으로 묶는다.**
  흐름이 여럿이면 `# ` 블록을 여러 개 쓴다.
- 최상위 불릿 = 작업 단위. `- 이름 — 설명` 형태. 설명이 군더더기면 이름만 쓴다.
- 하위 불릿 = 그 작업의 구성 요소. 공백 2칸 들여쓰기. 없으면 안 쓴다.
- 상태(완료·검증 완료 등)는 별도 섹션 없이 **그 줄 안에서** 표현한다.

## 3단계 — 규칙

- **출력에 레포명·시각·커밋해시·브랜치를 쓰지 않는다.** 수집 자료는 근거일 뿐 결과물이 아니다.
- 커밋 여러 개가 한 작업이면 **한 줄로 접는다.** 앞 커밋을 고친 `fix:` 는 원래 작업에 합친다.
- `feat:` `fix:` `chore:` 같은 prefix는 지우고 사람 말로 바꾼다.
- **커밋에 없는 내용을 지어내지 않는다.** 애매하면 커밋 제목을 그대로 쓴다.
- 커밋 제목이 `update` 처럼 내용이 없으면 그 줄은 **아예 빼거나** 한 줄로 뭉뚱그린다.
- 어제 보고서에 있던 항목이 오늘 이어졌으면 **같은 흐름 아래로 묶는다.** 어제 것을 다시 나열하지 않는다.
- 미커밋 변경이 있으면 해당 작업 줄 끝에 `(작업 중)` 만 붙인다. 별도 섹션을 만들지 않는다.
- **항목이 없는 제목은 쓰지 않는다.** 묶을 게 하나뿐이면 제목을 만들지 말고 다른 흐름에 넣는다.
- 같은 작업을 두 줄로 적지 않는다. 저장 직전에 **중복 줄이 없는지 확인한다.**
- 미커밋 파일 목록은 수집 자료에 이미 있다. **`git status` 를 따로 실행하지 않는다.**
- 보고서를 **한 번에 완성해서 한 번만 저장한다.** 저장한 파일을 다시 열어 고치지 않는다.

## 4단계 — 출력

**보고서 전체를 ```markdown 코드펜스 안에 넣어서 출력한다.**
그대로 복사해 다른 곳에 붙여 넣을 것이므로, 렌더링된 제목·불릿이 아니라 **원본 문자가 보여야 한다.**

펜스 밖에는 아무것도 쓰지 않는다. 인사말·설명·요약·후기 금지.

## 5단계 — 저장

같은 내용을 `$HOME/.standup/log/<오늘날짜>.md` 에 저장한다. 디렉터리가 없으면 만든다.
**파일에는 코드펜스를 넣지 않는다.** 펜스는 화면 출력용이고 파일은 원본 마크다운이어야 한다.

저장 후 펜스 다음 줄에 파일 경로만 한 줄 적는다.
